MANUAL DE EJECUCIÓN: SUBIDA DE PROYECTO A GITHUB

Paso 1: Guardar cambios en el repositorio local
Descripción: Registra todos los archivos modificados y creados en el historial de control de versiones de Git local.
Comando: git commit -m "Simula V0"

Paso 2: Renombrar la rama principal a main
Descripción: Cambia el nombre de la rama actual (por defecto master) a main para coincidir con la rama estándar de GitHub.
Comando: git branch -M main

Paso 3: Subir el código al servidor remoto y autenticarse
Descripción: Envía la rama main al servidor remoto (origin). Solicita usuario (sintesisLabEstudio) y contraseña (donde se ingresa el Personal Access Token / PAT).
Comando: git push -u origin main

Paso 4: Resolver conflicto de rechazo (Force Push)
Descripción: Soluciona el error ! [rejected] provocado por archivos previos creados automáticamente en GitHub (como un README.md), sobrescribiendo el remoto con la versión local.
Comando: git push -u origin main --force

Comando alternativo (en lugar de forzar):
Si se prefiere conservar el contenido remoto y fusionarlo con el local:
git pull origin main --allow-unrelated-histories
git push -u origin main

MANUAL DE GIT: RESOLUCIÓN DE CONFLICTOS AL HACER PUSH / PULL REBASE CON UNTRACKED
================================================================================

1. DESCRIPCIÓN DEL PROBLEMA
--------------------------------------------------------------------------------
Al intentar enviar cambios locales con 'git push', el servidor remoto rechazó 
la operación debido a que la rama remota contenía avances que no estaban en local.

Al ejecutar 'git pull origin main --rebase', el proceso se abortó porque existían 
archivos no rastreados (untracked files) en la carpeta 'desarrollo/' que colisionaban 
con los mismos archivos que venían desde GitHub.


2. MENSAJES DE ERROR RECIBIDOS
--------------------------------------------------------------------------------
- Error de Push rechazado:
  ! [rejected] main -> main (fetch first)
  error: failed to push some refs to 'https://github.com/.../Simula.git'

- Error de Pull abortado por archivos untracked:
  error: The following untracked working tree files would be overwritten by checkout:
         desarrollo/...
  Please move or remove them before you switch branches. Aborting


3. SECUENCIA DE COMANDOS PARA LA SOLUCIÓN (PASO A PASO)
--------------------------------------------------------------------------------

Paso 1: Guardar temporalmente el trabajo y los archivos no rastreados
> git stash --include-untracked

Paso 2: Traer los cambios remotos y reestructurar la historia local encima
> git pull origin main --rebase

Paso 3: Recuperar el trabajo resguardado desde el stash
> git stash pop

Paso 4: Subir los commits consolidados hacia GitHub
> git push origin main

Paso 5: Limpiar la memoria temporal del stash (Opcional)
> git stash drop


4. GLOSARIO Y CONCEPTOS CLAVE
--------------------------------------------------------------------------------
+-------------------------------+-------------------------------------------------------------------+
| COMANDO / CONCEPTO            | DESCRIPCIÓN Y USO EN EL CASO                                      |
+-------------------------------+-------------------------------------------------------------------+
| git pull origin main --rebase | Sincroniza la rama remota y coloca los commits locales al final   |
|                               | de la historia, evitando commits de merge innecesarios.           |
+-------------------------------+-------------------------------------------------------------------+
| git stash --include-untracked | Resguarda los cambios actuales y los archivos nuevos no rastreados|
|                               | (untracked), dejando el directorio de trabajo limpio.             |
+-------------------------------+-------------------------------------------------------------------+
| git stash pop                 | Aplica y restaura los cambios previamente guardados en el stash.  |
+-------------------------------+-------------------------------------------------------------------+
| git stash drop                | Borra el registro temporal almacenado en el stash.               |
+-------------------------------+-------------------------------------------------------------------+
| LF / CRLF Warning             | Advertencia del sistema sobre saltos de línea entre Unix (LF)     |
|                               | y Windows (CRLF). No interrumpe ni daña el flujo de trabajo.      |
